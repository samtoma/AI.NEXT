The change under test

FR-301 · lib/bkt.ts

Mastery stops being a rating and becomes a probability with an evidence trail behind it. The trace below is a real walk recorded against the local database, not an illustration.

The ceiling is the point. The posterior is clamped at 0.98, never 1.0, so a student can always be shown to have slipped — one wrong answer after fifteen correct still drops her to 0.874. That is invariant 3 of the BKT contract, and it is the one that matters: a model that saturates at certainty can never revise its mind about a student.

What is done, and what proves it

evidence, not assertion

  • Verified The content-parity gate catches its target failure A fresh scoped load reports 450 questions in total but only 421 live — Unit 1's 29 superseded rows. A totals-only check would have called that parity and the comparison would have quietly stopped meaning anything.
  • Verified Environment attribution on every row Read from configuration only, never inferred from the request host. A misconfigured stack produces obviously-wrong data rather than quietly-plausible pooled data.
  • Verified The retrieval seam — one place where grounding is composed Running it against a real graph found a column-name bug (src/dst versus src_id/dst_id) that would have failed every single tutor turn. It typechecked perfectly.
  • Verified Per-topic progress with no blended score anywhere The module computes no overall aggregate at all, so no caller can render one by accident. A student strong on three units and lost on a fourth is not "68%".
  • Built The isolated ainext-mvp1 stack Own volumes, own port, own password, loader behind a profile. Written and reviewed; it has never been brought up on the box.
  • Built The explanation and refutation pipeline Dry-run verified from manifest through assembler. Every entry it loads is forced to reviewed = false, which is what keeps the review-gate suspension honest and reversible.
  • Blocked Crisis escalation to a named human Everything else in safety is buildable the moment a recipient is named. An unmonitored channel produces a record that looks like a safeguard and is not one.

Why the design system got requirements

FR-1001–1010

The progress dashboard shipped with a burnt-sienna mastery ramp. The design handoff forbids red outright — a wrong answer greys out and invites a retry — because the student we are building for is afraid of looking stupid, and a red bar is what that fear looks like on a screen. Nothing in the requirement set could have caught it. Now ten requirements can.

What we need decided

in this order

T067 · blocks Phase 11 · blocks real students

Name the human who receives a crisis flag

Not a mailbox — a person, and what we expect them to do when it arrives. Everything else in safety is written and waiting. Until this lands we cannot put the environment in front of a child, and shipping it without a named recipient would be worse than shipping nothing: it produces an audit trail that looks like a safeguard.

FR-306 and FR-402

Build these two, or defer them on the record

Mid-year placement by assessment, and exam preparation by high-yield topic. Both currently read as in scope and neither is being built. An in-scope requirement nobody is building is more dangerous than a deferred one, because the plan still counts on it.

SC-004 and SC-007

Two success criteria no longer hold

SC-004 still measures "verified signups", which the profile picker replaced. SC-007 is not buildable as written — the metric has no data source. If we are going to judge the experiment by these numbers, they have to be numbers we can actually produce.

design · reversible

Confirm the master variant over Play

The handoff ships two and forbids mixing them. Prep-3 is fourteen to fifteen, inside both bands. Master is implemented, on the reasoning that we are already varying the teaching model and a second visual variable would confound the result. Reversing it is a token swap.

the honest headline

Everything measurable is done. Nothing has met the box.

The teaching core, the environment attribution, the content-parity gate and the whole design language are built and were exercised against real data — a loaded database, passing tests, rendered pages. The deployment half is written, reviewed, and entirely untested, because it needs a machine this work has never had access to. That is the gap between here and a pilot, and it is a smaller gap than it sounds.
